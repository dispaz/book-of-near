# Topic 5.1: Trusted Execution Environments (TEEs) and Confidential AI Inference

## In one sentence

NEAR AI Cloud leverages Trusted Execution Environments (TEEs) and confidential GPUs to ensure that AI prompts and model weights are cryptographically isolated from cloud operators and provably unaltered via remote hardware attestations.

## The problem it solves

When users interact with centralized AI services (such as OpenAI, Anthropic, or standard AWS cloud instances), the server administrator, cloud hosting provider, and intermediate operating systems have full plaintext visibility into every prompt, token, and generated output. Furthermore, users have no mathematical proof that the requested model weights actually generated the response without censorship or tampering. [near-ai-vision]

## How it works on NEAR

**Trusted Execution Environments (TEEs).**
- A TEE (e.g. Intel TDX, AMD SEV-SNP) is a secure, isolated area within a CPU chip. [tee-overview]
- Memory used by code running inside a TEE is encrypted in hardware by memory encryption engines with keys burned into silicon. [tee-overview]
- Neither host operating system administrators, hypervisors, cloud operators, nor physical technicians with direct hardware access can inspect or alter memory contents (the "triple lockout"). [near-ai-vision]

**Confidential GPUs (NVIDIA H100/H200).**
- Traditional TEEs only protected CPU compute, making fast LLM inference impossible. [nvidia-cc]
- Modern confidential GPUs encrypt the PCIe connection between CPU and GPU, ensuring massive language models can execute at full speed inside an encrypted perimeter. [nvidia-cc]

**Remote Attestation.**
- Before trusting an enclave, a client requests an **attestation quote**. [tee-overview]
- The processor hardware signs a cryptographic measurement (a hash of the initial enclave code, operating state, and public keys) with an asymmetric private key burned into the silicon during semiconductor manufacturing. [tee-overview]
- Anyone can verify this signature against the chip manufacturer's public root certificate (e.g. Intel or NVIDIA PKI), mathematically proving that the exact intended, un-tampered AI code is running inside a genuine secure enclave. [near-ai-vision]

**Stake-to-Compute Economics.**
- In addition to standard pay-per-token models, NEAR AI allows users and developers to stake native NEAR tokens to earn recurring compute credits for private inference. [near-ai-vision]

## Words to know

- **TEE (Trusted Execution Environment):** A hardware-isolated and encrypted compute enclave within a processor.
- **Confidential Computing:** Running computations while keeping data in memory encrypted at all times.
- **Remote Attestation:** A cryptographic proof signed by physical hardware certifying that a specific program is running in an authentic secure enclave.
- **Attestation Quote:** The binary data package containing hardware measurements and silicon signatures.
- **User-Owned AI:** The vision where individuals retain sovereign ownership over models, personal data, and agent actions.

## Common misunderstandings

- **"Encryption in transit (HTTPS) protects my prompt from the AI provider."** HTTPS only encrypts data as it travels across the internet. Once it reaches the server, the host decrypts it into plaintext RAM. A TEE keeps data encrypted even while in RAM during execution. [tee-overview]
- **"TEEs run on a blockchain."** No. TEEs run on physical high-performance silicon servers (e.g. NVIDIA H100 clusters). The blockchain acts as the registry, payment coordinator, and settlement verifier. [near-ai-vision]
- **"Attestation can be faked by server software."** Attestation signatures are generated by silicon hardware fuses during manufacturing; software running on the host has no access to the private signing key. [tee-overview]

## Compared with Web2 AI & Other Networks

- **Web2 AI (OpenAI / Google):** Completely centralized; providers log prompts, fine-tune models on user data, and operate black-box servers with zero cryptographic verification. [near-ai-vision]
- **Apple Private Cloud Compute:** Uses hardware enclaves, but operates as a closed, proprietary Apple-only ecosystem. [apple-pcc]
- **NEAR AI Cloud:** Open-source, permissionless, OpenAI-compatible API endpoints verifiable by any client via open remote attestation standards. [near-ai-vision]

## Strengths and weaknesses (feeds the Honest take)

**Strengths:**
- Mathematical privacy: True hardware-enforced prompt confidentiality against cloud providers. [tee-overview]
- Verifiable provenance: Cryptographic remote attestation guarantees exact model code and output authenticity. [near-ai-vision]
- Standard interface: OpenAI-compatible REST API allows dropping into existing applications seamlessly. [near-ai-vision]

**Weaknesses:**
- Hardware vendor trust: Security relies on the physical silicon and root keys issued by Intel/AMD/NVIDIA remaining free of manufacturing vulnerabilities. [tee-overview]
- Side-channel vulnerabilities: Sophisticated physical side-channel attacks (e.g. cache timing, power analysis) require continuous microcode patching by chipmakers. [tee-overview]
