# Lesson 5.1: Ask a private AI and verify it

Issue: #84 (first drafted under #38). Target time: 5 minutes. Chain access: none on NEAR. NEAR AI Cloud's public attestation endpoint: demo mode uses a report recorded on 13 Nov 2026; testnet mode fetches a fresh one with the learner's own nonce. The checks run for real in the browser either way. Views: 2D and 3D, one shared state.

Facts come from `docs/lessons/stage-5/5.1-topic.md`. Anything else is marked (unverified).

## 1. Learning goals

1. Explain how a Trusted Execution Environment (TEE) keeps AI prompts away from cloud operators.
2. Fetch a hardware attestation quote and check its signatures up to the chipmaker's root.
3. Understand why confidential computing matters for user-owned AI.

## 2. Steps

### Step 1: Who can read your prompts?
- **Caption:** Who can read your prompts to an AI?
- **Explain:** Most AI services run on ordinary cloud servers. HTTPS protects your prompt on the way, but the server decrypts it into its memory to work on it, and the people who run that server can read it there, log it or keep it. NEAR AI Cloud runs models inside hardware enclaves instead.
- **Scene:** Your terminal; an ordinary cloud server (lid open, memory readable) at the back; a sealed enclave (a chip inside a perimeter) in front. Next is open.

### Step 2: The hardware enclave (TEE)
- **Caption:** A Trusted Execution Environment (TEE) seals memory inside the chip.
- **Explain:** A TEE is a sealed area of a processor, such as Intel TDX (Trust Domain Extensions: Intel's TEE, which seals a whole virtual machine). The chip encrypts the memory the code inside uses, with keys that never leave the chip. The operating system, the cloud operator and a technician with the machine in hand are all locked out: the **triple lockout**. Try it: read both machines' memory as root.
- **Action:** "Read the memory as root" (gated). The server's memory shows the prompt in plain text; the enclave's shows noise. Labelled as an illustration, not a real memory dump.

### Step 3: Send a prompt to the AI tutor
- **Caption:** Ask the Book of NEAR tutor a question.
- **Explain:** On NEAR AI Cloud the model runs inside an enclave, and your prompt travels over an encrypted channel straight into it. In this edition the answer is written in advance: a live answer needs a NEAR AI Cloud API key, and a public book cannot ship one.
- **Action:** Three sample questions, then "Send prompt" (gated). The answer arrives a few words at a time (all at once under reduced motion), labelled "Pre-written answer, not generated live".

### Step 4: Fetch the attestation quote
- **Caption:** How do you know it really ran in an enclave? Ask the chip for proof.
- **Explain:** Anyone can claim to use a TEE. The proof is an **attestation quote**: a report the chip signs with a key only genuine Intel hardware holds. It carries measurements (hashes of the loaded code) and 64 bytes chosen by the code inside: the model's signing address and a nonce, so an old quote cannot pass as new.
- **Action:** "Fetch attestation quote" (gated). Shows: model, "Intel TDX quote, 5006 bytes", MRTD, RTMR0–3, report data, the certificate chain (PCK Certificate → PCK Platform CA → Intel SGX Root CA), and the NVIDIA GPU evidence count (not checked).
- **Demo data:** NEAR AI Cloud report for `Qwen/Qwen3.8-27B`, recorded on 13 Nov 2026 (`src/chain/nearai/recorded-attestation.json`), labelled so.

### Step 5: Verify the quote
- **Caption:** Verify the quote yourself, in your browser.
- **Explain:** Your browser checks each signature. The report is signed by an attestation key (a key made in the machine to sign reports). Intel's quoting enclave (a small Intel enclave beside it) vouches for that key. The chip's PCK certificate (Intel's certificate for this one chip) signs that, and it chains up to Intel's published root. Change one byte of the report and a check fails. Try it once it passes.
- **Action:** "Verify in my browser" (gated): eight checks (the quote's signature, the quoting enclave's binding and signature, the certificate chain, Intel's root fingerprint, the report data, the measurements, and that the enclave is not in debug mode), then "Verified: signed by Intel TDX hardware, checked in your browser." Optional: "Change one byte and verify again", which fails. A note lists what is not checked. A live quote (testnet mode) that fails a check or cannot be read is replaced by the recorded one, with a notice, so the step can still be finished.
- **Evidence:** `{ attestationHash, verified: "true", tee, model, quoteSource, recordedOn, checksPassed }`.

## 3. Check

**Q1. What makes a TEE different from ordinary cloud hosting?**
- A. The processor encrypts its memory in hardware, so even root admins cannot read it. **(correct)**
- B. It makes users pay with Bitcoin instead of credit cards. *Wrong: how you pay has nothing to do with hardware security.*
- C. It deletes your data after 30 days. *Wrong: an enclave protects data while it is in memory and in use.*

**Q2. What is a remote attestation quote?**
- A. A report signed by the chip that proves which code runs inside a genuine enclave. **(correct)**
- B. A price quote from an AI sales team. *Wrong: it is a signed hardware report, not a price.*
- C. A legal contract between NEAR and a chipmaker. *Wrong: the hardware makes and signs it, automatically.*

**Q3. The host's root admin dumps the server's memory while the AI runs in an enclave. What do they see?**
- A. Encrypted noise. **(correct)**
- B. Your prompts in plain text. *Wrong: the chip keeps the enclave's memory encrypted.*
- C. Your wallet's seed phrase. *Wrong: your seed phrase never goes to the AI server at all.*

## 4. Honest take

**Strengths:**
- **Real prompt privacy:** the chip keeps the enclave's memory encrypted, so the cloud operator cannot read your conversation while it runs. [tee-overview]
- **Proof you can check:** the quote is signed by the hardware and chains up to Intel's published root; the browser checked it. [near-ai-vision] [recorded-report]
- **A familiar interface:** an OpenAI-compatible API, so existing apps can switch with little change. [near-ai-vision]

**Weaknesses:**
- **You still trust the chipmaker:** the proof is only as good as Intel's (and NVIDIA's) hardware and root keys. [tee-overview]
- **Side channels:** timing or power attacks can leak secrets from enclaves; chipmakers keep patching firmware. [tee-overview]
- **The page checks the signatures and the debug flag, not everything:** not revocation lists (CRLs), the firmware level (TCB), certificate dates, the quoting enclave's identity (QE identity), MRSEAM (the identity of Intel's TDX module), the NVIDIA GPU evidence, or what the measured code does. [recorded-report]
- **Pre-written answers:** chat needs an API key, so this edition shows a real quote but not a live answer.

Compared with: **ordinary cloud AI** (the operator can read every prompt; nothing to verify) and **Apple Private Cloud Compute** (enclaves too, but closed and Apple-only). [apple-pcc]
