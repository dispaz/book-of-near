# Lesson 5.2: An agent with no owner

Issue: #39. Target time: 5 minutes. Chain access: read-only or demo mode. Views: 2D and 3D, one shared state.

Facts come from `docs/lessons/stage-5/5.2-topic.md`. Anything else is marked (unverified).

## 1. Learning goals

1. Explain how combining TEE enclaves with Chain Signatures produces true AI agent autonomy.
2. Contrast a sovereign Shade Agent with traditional bots whose keys sit in developer `.env` files.
3. Observe how an autonomous agent signs multichain transactions with zero human backdoors.

## 2. Steps

### Step 1: The fake autonomy of Web3 bots
- **Caption:** Most "AI agents" today are just bots whose keys sit in a developer's `.env` file.
- **Explain:** If a developer controls the private key, the AI is not autonomous. The creator can drain the treasury, front-run users, or be forced to hand over credentials. True autonomy requires that **no human holds the key**.
- **Scene:** A bot connected to a developer laptop with an exposed private key file. Next is open.

### Step 2: The Shade Agent architecture
- **Caption:** A Shade Agent runs inside a TEE and derives multichain accounts through NEAR Chain Signatures.
- **Explain:** The AI's code runs sealed inside a hardware enclave. Using NEAR's MPC network, the enclave requests a derived address tied to its exact code hash. Only the code inside the enclave can sign for that account.
- **Scene:** The AI brain inside the TEE box connected directly to the MPC validator ring. Next is open.

### Step 3: Inspect the agent's credentials
- **Caption:** Examine the agent's on-chain identity: a NEAR account and an Ethereum treasury address.
- **Explain:** The agent owns `portfolio-bot.near` and a derived Ethereum address `0x7a...`. It has received 1,000 USDC in trading funds.
- **Action:** Inspect the address derivation path and attestation measurement. Next unlocks when inspected.

### Step 4: Simulate a rogue creator attack
- **Caption:** Can the original developer steal the agent's funds? Watch the attack bounce off.
- **Explain:** The developer attempts to sign a transfer transaction using their creator key. The NEAR MPC contract refuses: the derivation path belongs exclusively to the enclave measurement. The developer is locked out.
- **Action:** Button "Attempt creator withdrawal". Shows refusal: `Unauthorized: Caller is not the verified enclave`.

### Step 5: Autonomous execution
- **Caption:** The agent detects an arbitrage opportunity and executes a cross-chain swap on its own.
- **Explain:** Based purely on its internal market model, the agent dispatches a signed intent to the solver network and updates its balances on both chains.
- **Action:** Button "Trigger agent run". Watch the agent analyze data, sign via `v1.signer`, and complete the rebalance.
- **Evidence:** `{ agentAccountId, attackDefended: true }`.

## 3. Check

**Q1. Why are traditional trading bots not truly autonomous?**
- A. A human developer still possesses the private keys and can override or drain the bot at will. **(correct)**
- B. Because Python cannot process cryptocurrency transactions. *Wrong: Python connects to blockchains easily.*
- C. Because bots cannot connect to Wi-Fi. *Wrong: bots run on cloud servers.*

**Q2. How does a Shade Agent obtain its blockchain accounts?**
- A. Through NEAR Chain Signatures tied deterministically to the enclave's code measurement. **(correct)**
- B. By buying stolen private keys on the dark web. *Wrong: keys are derived cryptographically through MPC.*
- C. By asking a bank to open an account. *Wrong: blockchain accounts require no banking approval.*

**Q3. If the developer who created the Shade Agent wants to steal its treasury, what happens?**
- A. The protocol refuses the transaction because the developer does not have access to the enclave keys. **(correct)**
- B. The developer easily enters their master password. *Wrong: there are no master passwords in asymmetric cryptography.*
- C. The blockchain crashes. *Wrong: the blockchain handles invalid transactions smoothly.*

## 4. Honest take

**Strengths:**
- **Zero human backdoor:** The creator cannot rug-pull or manipulate treasury funds held by the enclave. [shade-agents]
- **Native multichain power:** Controls accounts on Bitcoin, Ethereum, and Solana through NEAR Chain Signatures. [near-chain-sigs]
- **Complex off-chain intelligence:** Can run modern LLM models without paying prohibitive on-chain computation fees. [near-ai-vision]

**Weaknesses:**
- **Single server availability:** If the physical machine running the enclave loses power, the agent goes dark until migrated. [tee-overview]
- **Bug irreversibility:** If an agent has a flaw in its open-source logic, funds can be lost in bad trades without an emergency pause mechanism. [shade-agents]

Compared with: **Human-operated multi-sig wallets** (Safe / AstroDAO) and **On-chain smart contract bots** (Autonolas).
