# Lesson 0.3: Send a transaction and watch it

Issue: #10. Target time: 5 minutes. Chain access: testnet (real transfer from the practice account) or demo mode (recorded timings). Stays generic: no shards, chunks or receipts by name. Stage 2 opens the box.

## 1. Learning goals

1. Name the five stages of a transaction: build, sign, broadcast, included, final.
2. Explain nonce, gas and fee, RPC node and block explorer in one sentence each.
3. Read your own transaction in a block explorer.

## 2. Steps

### Step 1: Your practice account

- **Caption:** This is your practice account on NEAR testnet. Testnet coins are free and worth nothing, so mistakes cost nothing.
- **Explain:** **Testnet** is a copy of NEAR for practice. Its tokens have no value. **Mainnet** is the real network. Your practice account is an implicit account, like in 0.2. The app funded it from a **faucet**, a service that gives out free testnet tokens.
- **Action:** Scene shows the practice account block with its address and balance (e.g. 5 NEAR). If no practice account exists, the app creates and funds one, or falls back to demo mode with a notice. Next unlocks when a balance is shown.

### Step 2: Build the transaction

- **Caption:** Fill in who sends, who receives and how much. The app adds a nonce and a recent block hash.
- **Explain:** A transaction names the signer, the receiver and the actions, here one transfer. The **nonce** is a counter: each new transaction from a key must use a higher number, so an old one cannot be replayed. The recent **block hash** makes the transaction expire if it waits too long.
- **Action:** A form shows sender (fixed), receiver (fixed, the app's return account) and amount (0.01 NEAR, editable from 0.001 to 0.1). Nonce and block hash fill in from the chain (or demo data). Learner presses **Build**; the "Build" light turns on. Next unlocks after Build.

### Step 3: Gas and the fee

- **Caption:** Every transaction pays a small fee for the work it causes. On NEAR a simple transfer costs about 0.000045 NEAR.
- **Explain:** **Gas** measures the work a transaction makes the network do. Each action has a fixed gas cost. The **fee** is gas times the gas price. NEAR takes a bit more up front and refunds the extra about a block later, so your balance dips slightly more, then recovers.
- **Action:** Fee panel: "Gas: 0.45 Tgas. Fee at the minimum price: 0.000045 NEAR. Held up front: about 0.00045 NEAR. Refund: the difference." Learner taps **Got it**. Next unlocks after the tap.

### Step 4: Sign it

- **Caption:** Your private key signs the transaction, just like the message in 0.2. Its hash becomes the transaction ID.
- **Explain:** The wallet hashes the transaction (SHA-256) and signs that hash with the private key. Anyone can verify it with your public key. The hash is also the **transaction ID**, a unique name you can look up later. Signing happens on your device, with no network.
- **Action:** Learner presses **Sign**. The key stamps the transaction; the "Sign" light turns on and the transaction ID appears (base58, about 44 characters). Next unlocks after signing.

### Step 5: Broadcast through an RPC node

- **Caption:** The signed transaction goes to an RPC node: a server that passes it into the network and answers questions about it.
- **Explain:** An **RPC node** is a computer connected to the network that apps talk to. It forwards your transaction to the validators, the computers that make blocks. It can also report status. You trust it to answer honestly, so apps often keep a backup node.
- **Action:** Learner presses **Send**. The transaction flies from the page to an "RPC" block and on into the network. "Broadcast" lights up when the RPC accepts it. On error the lesson shows the message and offers demo mode. Next unlocks automatically once the next stage starts.

### Step 6: Included in a block

- **Caption:** A validator put your transaction in a block. The coins move, but the block is not final yet.
- **Explain:** Being **included** means the transaction is written in a new block. The transfer runs and balances change. A brand-new block could in rare cases still be replaced, so careful apps wait one more step. On NEAR, a new block comes about every 0.6 to 1 second.
- **Action:** A block drops onto the chain with the transaction inside. "Included" lights up. The sender's balance falls; the receiver's rises. Pipeline advances on its own; Next stays locked until "Final".

### Step 7: Final

- **Caption:** Final: the network has agreed this block will never change. NEAR docs put this at about 1.2 seconds.
- **Explain:** **Finality** is the point where a transaction cannot be reversed. NEAR's docs give about 1.2 seconds. Ethereum's site says about 15 minutes. Bitcoin has no fixed point; people wait for more blocks on top. A small gas refund also lands now.
- **Action:** "Final" lights up with a stopwatch showing the time from Send. Balance ticks up slightly as the refund lands. A comparison strip shows NEAR ~1.2 s, Ethereum ~15 min. Next unlocks.

### Step 8: Look it up in a block explorer

- **Caption:** A block explorer is a public website that shows every transaction. Open yours on NearBlocks.
- **Explain:** A **block explorer** reads the chain and shows it as web pages: blocks, accounts and transactions. Anyone can look up any transaction. That is the public side of a blockchain, from 0.1. NearBlocks is a popular NEAR explorer.
- **Action:** Button **Open in NearBlocks** links to `https://testnet.nearblocks.io/txns/<txHash>` (new tab). In demo mode the button opens an in-app mock explorer card with the same fields (hash, from, to, amount, fee, status) and a note that the hash is not on chain. Next unlocks after opening either.

### Step 9: Quick check

- **Caption:** Three quick questions. Then the honest take.
- **Explain:** (none)
- **Action:** Check (section 4), then Honest take. Completion record includes the transaction ID as evidence (testnet) or the demo hash flagged `demo: true`.

## 3. Glossary terms introduced

- **Testnet / mainnet:** the practice network with valueless tokens / the real network.
- **Faucet:** a service that gives out free testnet tokens.
- **Nonce:** a counter per key; each transaction must use a higher one, which blocks replays.
- **Block hash (in a transaction):** a recent block's hash; the transaction expires if that block gets too old.
- **Gas:** a measure of the work a transaction causes. **Tgas** = 10^12 gas.
- **Fee:** gas times gas price, paid in NEAR.
- **yoctoNEAR:** the smallest unit; 1 NEAR = 10^24 yoctoNEAR (shown only in the "more" panel).
- **Transaction ID (hash):** the unique name of a transaction.
- **RPC node:** a server apps use to send transactions and read the chain.
- **Validator:** a computer that makes and checks blocks (named only; Stage 2 goes deeper).
- **Included / final (finality):** in a block / guaranteed never to change.
- **Block explorer:** a public website showing chain data.

## 4. Check

**Q1. Put the stages in order.**
- A. Build, sign, broadcast, included, final. **(correct)**
- B. Sign, build, included, broadcast, final. *Wrong: you must build a transaction before you can sign it, and broadcast it before it can be included.*
- C. Build, broadcast, sign, final, included. *Wrong: the network rejects unsigned transactions, and a block must include it before it is final.*

**Q2. What does an RPC node do?**
- A. It passes your signed transaction into the network and answers questions about the chain. **(correct)**
- B. It holds your private key and signs for you. *Wrong: signing happens on your device; the RPC node only sees the signed result.*
- C. It decides the gas price. *Wrong: the network sets the gas price from how full recent blocks were.*
- D. It is the website where you look up transactions. *Wrong: that is a block explorer.*

**Q3. Why does each transaction carry a nonce?**
- A. So the same signed transaction cannot be sent again to move coins twice. **(correct)**
- B. To pay the fee. *Wrong: the fee comes from gas times the gas price.*
- C. To hide the amount. *Wrong: amounts are public; the nonce is just a counter.*
- D. To choose which validator handles it. *Wrong: the nonce does not pick a validator.*

## 5. Honest take

**Strengths**
- **Fast finality.** NEAR docs give finality around 1.2 s. ethereum.org says an Ethereum block takes about 15 minutes to finalize, and Bitcoin has no fixed finality point; confidence grows as blocks are added on top. [near-finality] [eth-ssf] [bitcoin-chain]
- **Low, predictable fees.** Each action has a fixed gas cost; a transfer is 0.45 Tgas, about 0.000045 NEAR at the minimum gas price. The price moves only 1% per block. Attaching extra gas does not make a transaction faster. [near-gas]
- **Choose how long to wait.** The RPC `send_tx` call lets an app return at any stage, from "sent" to fully final, so apps can show progress honestly. [near-rpc-tx]

**Weaknesses**
- **"Sent" is not "done".** The docs warn that a successful RPC reply does not prove later steps succeeded. Apps must check final status. The default RPC wait level is not full finality. [near-lifecycle] [near-rpc-tx]
- **You trust your RPC node.** Most apps read the chain through a node someone else runs. A faulty or overloaded node can be slow or wrong, and the default wait limit is 10 seconds. This is true on Ethereum and Bitcoin too. [near-rpc-tx]
- **The balance dance confuses beginners.** NEAR holds gas at a buy price (minimum 0.001 NEAR per Tgas), then refunds the difference a block later. For a transfer, about ten times the final fee is held briefly. [near-gas]
- **Docs disagree on block time.** One page says ~600 ms, another says ~1 second. Treat any single figure as approximate. [near-finality] [near-gas]
