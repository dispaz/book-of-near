## In one sentence

A blockchain is a shared, append-only ledger of blocks linked by cryptographic hashes, making past history impossible to alter without visibly breaking every subsequent link.

## The problem it solves

In a peer-to-peer network without a central bank or middleman, participants need a way to agree on the single true history of balances and transactions without trusting any single participant. If anyone could rewrite past history, digital money could be spent twice (the double-spending problem). [btc-whitepaper]

## How it works

**The Shared Ledger.**
- Accounts have balances. Transactions move coins from one person to another (e.g. Ana sends 3 coins to Ben). [near-basics]
- Transactions are grouped into batches called **blocks**. [near-basics]

**Cryptographic Hashing.**
- A hash function (like SHA-256) takes any input text and produces a fixed-length string of characters (a digital fingerprint). [near-basics]
- Even a tiny change (e.g., changing "Ana sends 3" to "Ana sends 9") changes the entire hash completely and unpredictably (the avalanche effect). [near-basics]

**The Chain of Blocks.**
- Every new block records two essential things:
  1. Its own list of new transactions.
  2. The hash of the previous block (`prev_hash`). [near-basics]
- This mathematical link binds the blocks into an unbroken chain:
  `Block 0 (Genesis) -> Block 1 -> Block 2 -> Block 3`

**Why History is Tamper-Evident.**
- If an attacker tampers with an old transaction in Block 1, Block 1's hash changes immediately. [near-basics]
- Because Block 2 contains the old hash of Block 1 in its `prev_hash` field, the link between Block 1 and Block 2 breaks. [near-basics]
- All subsequent blocks become invalid unless the attacker recomputes every subsequent block's hash. In a decentralized network, other nodes reject the tampered branch because honest nodes agree on the canonical valid chain. [btc-whitepaper]

## Words to know

- **Ledger:** A permanent record of financial transactions and account balances.
- **Transaction:** An instruction to move value or execute state changes.
- **Block:** A packaged collection of transactions validated and added to the chain together.
- **Hash:** A mathematical fingerprint generated by a one-way cryptographic function (like SHA-256).
- **Genesis Block:** The very first block (Block #0) in a blockchain from which all subsequent blocks derive.

## Common misunderstandings

- **"A blockchain is just an encrypted database."** No. Blockchain data is typically public and unencrypted; what cryptography provides is proof of integrity and non-tamperability, not secrecy. [near-basics]
- **"Blocks can be edited if you have an admin key."** Blockchains have no administrator backdoors. Tampering with an old block breaks cryptographic links on all peer nodes. [btc-whitepaper]

## Compared with Bitcoin & Ethereum

- **Concept:** Universal across all blockchains (Bitcoin, Ethereum, NEAR). Every major blockchain uses cryptographic hash chaining (`prev_hash`) to link blocks.
- **Consensus & Speed:** Bitcoin produces blocks roughly every 10 minutes (Proof of Work). Ethereum produces blocks every 12 seconds (Proof of Stake). NEAR produces blocks roughly every 1 second or less (Doomslug Proof of Stake). [near-basics]

## Strengths and weaknesses (feeds the Honest take)

**Strengths:**
- Tamper-evident: Altering past records is mathematically evident to every node. [btc-whitepaper]
- Trustless agreement: Participants agree on state without a central authority or clearinghouse. [near-basics]

**Weaknesses:**
- Append-only overhead: Storage requirements grow continuously over time as new blocks are added. [near-storage]
- Finality latency: Transactions are not instantaneous like centralized databases; they require network propagation and consensus confirmation. [near-basics]
